# Product Decision Log

Extracted from [[Meta/Product]] on 2026-07-30. Rows are kept verbatim; where a later
decision reversed one, or where the codebase has since made a row false, the row carries
an inline **Reversed** or **No longer true** annotation rather than being deleted. A
decision that turned out wrong is more useful than a decision quietly removed — but a
row that reads as current when it is not is a trap.

| 2026-02-03 | `cru.tools.call` is highest-priority plugin primitive | Low effort (tools exist on Rust side, this is Lua binding + permission check) but unlocks the most new plugin categories: autonomous loops, smart importers, digest generators. Without it, plugins can only react to events — not do intelligent work. ~~**No longer true in one part:** the permission check was never built; `DaemonToolsBridge::call_tool` runs tools with a default `ExecutionContext` and no gate~~ **Annotation struck 2026-08-18:** the gate exists and is fail-closed. `DaemonToolsBridge` holds a `PermissionEngine` and an isolation registry, both checked before execution (`tools_bridge.rs:95-141`): an operator `deny` is absolute, an `ask` rule refuses because a Lua call has nobody to prompt, and an undecided tool passes only if `is_safe`. | 2026-02-03 | `cru.service` lifecycle before `cru.messaging` adapter | Service lifecycle (start/stop/health, supervised restart, config validation) is the foundation messaging adapters compose on. Discord, Telegram, calendar pollers, auto-linkers are all services. Build the general pattern first |
| 2026-02-03 | `cru.messaging` adapter: extract from two implementations | Don't speculate the adapter shape from Discord alone. Build Telegram or Matrix adapter, then extract the common trait. The receive→respond→format loop is identical; platform variance is in transport and API shape |
| 2026-02-03 | Fennel is opt-in power tool, not default path | Lua examples first in all docs; Fennel shown alongside. Macros are genuinely valuable (`defservice`, `deftool` could halve plugin boilerplate) but LuaLS doesn't understand Fennel — devs trade IDE ergonomics for language ergonomics. **Reversed 2026-08-30 — see the Luau row below.** |
| 2026-02-05 | Agent learning as notes, not opaque DB | Informed by Agno framework analysis. Agno uses six opaque DB-backed learning stores. Crucible's approach: agent memory stored as wikilinked atomic notes (zettelkasten-style) in kiln. Human-readable, editable, searchable via existing graph. Strictly better — same capabilities plus human review/edit. Local embeddings + metadata (wikilinks, tags, frontmatter) provide rich fetchable context without custom storage |
| 2026-02-05 | Two-tier extensibility: core Rust + runtime Lua | Core features (precognition, auto-linking, team patterns) in Rust for performance, toggleable via `:set`. Higher-level behaviors (entity-memory, session-digest) as default runtime Lua plugins. Both show in `:plugins` with provenance. Matches Neovim's architecture: C core + bundled Lua plugins. **No longer true:** every instance cited is gone — team patterns removed 2026-05-12, `session-digest` removed in the same prune, `entity-memory` never existed in the tree. `:plugins` also does not show provenance (`PluginStatusEntry` has no `source` field). The *principle* survives; the examples do not. Bundled set today: `daily-notes`, `discord`, `graph-view`, `oci`, `reflection`, `review`, `todo-list`, `web-search`, `worktree` |
| 2026-02-05 | Default runtime plugins (Neovim-style) | Ship bundled Lua plugins at `$CRUCIBLE_RUNTIME/plugins/`; lowest-priority in discovery path; user plugins shadow by name. Source code serves as reference documentation. Plugins: `entity-memory` (facts → atomic notes), `session-digest` (session summaries → linked notes). **No longer true:** neither named plugin ships. The bundled set is nine plugins today, and the tree now travels inside the binary, so an installed user does get them |
| 2026-02-05 | Team patterns as core Rust, not Lua plugins | Multi-agent orchestration (supervisor, router, broadcast) is fundamental infrastructure, not optional behavior. Implemented in Rust, builds on existing subagent spawning. Configurable via `:set team.default_pattern`. Lua hooks can intercept delegation decisions. **Reversed 2026-05-12 — see next row.** |
| 2026-05-12 | Team patterns as Lua recipes, not Rust orchestrators | The hardcoded `Supervisor` / `Router` / `Broadcast` types each picked one delegation shape (Lua decider, single-shot classifier, parallel fan-out) and shut out variants. Users want to script delegation with primitives — supervisor + LLM judge, router + regex, supervisor + DAG, fan-in pipelines, retries. `cru.session.{create, configure_agent, send_and_collect, end_session, collect_subagents}` already covers it; the three patterns become 5–20 line recipes in [[Help/Delegation Patterns]]. ~1984 LOC removed. The 2026-02-05 "fundamental infrastructure" framing was wrong: delegation *primitives* are infrastructure, delegation *patterns* are user code |
| 2026-08-30 | Luau is the runtime; Fennel is removed | One language, one runtime story. Luau gives type annotations and `--!strict` with no source-to-source compiler, which is the DX the 2026-02-03 row wanted from macros and could not have with LuaLS. Fennel needed PUC Lua's `debug` library and a 255KB vendored compiler for a single shipped plugin. What the swap costs is real and is paid by the host, not by plugin authors: Luau has no `package.path` (a host resolver owns `require`), and no `io` and no file half of `os` (`luau_compat` provides them, `io.popen` and `os.execute` included). See `crucible-lua/src/modules.rs` and `luau_compat.rs` |
| 2026-08-30 | Declared types are one Rust-owned model | A tool's declared parameter types feed three surfaces — the JSON Schema an agent reads, the Luau declarations an author checks against, and the messages a human reads. They were three independent readings of the same strings, and the JSON Schema one rendered everything it did not recognise as `"string"`. `signature::LuaType` is the single reading; an unreadable declaration refuses the load instead of inventing a shape. `cru plugin check` is the gate, and reports a missing `luau-analyze` as SKIPPED rather than as a pass |
| 2026-02-05 | SQLite is default storage | Product map updated to reflect SQLite as default, SurrealDB as advanced option. Docs (CLAUDE.md, Systems.md) corrected. SQLite is fast, lightweight, recommended for single-user local-first usage. **No longer true in one part:** SurrealDB is not an advanced option — `crucible-surrealdb` was deleted 2026-02-23 (17K LOC). SQLite is the only backend, and `[storage] backend` is not a config key |
| 2026-03-21 | Context & Execution as core runtime | Competitive analysis (Aider, CrewAI, LangGraph, Semantic Kernel) revealed 5 features universally treated as core: context window management, execution limits, prompt caching, agent undo, output validation. All too fundamental for plugins. Partial infrastructure already exists (context_ops module, UndoTree, session.compact, genai CacheControl) |
| 2026-03-21 | Prompt caching via genai (no new deps) | genai v0.5.3 already exposes `CacheControl::Ephemeral`; Crucible just needs to import and use it. Anthropic: 90% savings on cached reads. OpenAI: automatic, no code needed. No Rust framework (Rig, kalosm) provides this — all DIY |
| 2026-03-21 | Token counting: heuristic, not library | No accurate local Claude 3+ tokenizer exists. tiktoken-rs covers OpenAI only. char/4 heuristic calibrated against provider usage stats is sufficient for budget decisions. Exact counts only matter for billing (provider reports post-hoc) |
| 2026-03-21 | Context strategies: truncate default, summarize opt-in | Truncate (drop oldest) is simple, no LLM call, good default. Summarize is expensive but preserves context — opt-in via `:set context_strategy=summarize`. Sliding window is middle ground. Prompt caching reduces urgency (cached prefix is cheap to resend). ~~**No longer true:** no strategy runs. `GenaiAgentHandle.context_budget` is never set from `SessionAgent`, so `enforce_context_budget` returns `NoChange` on every request~~ **Annotation struck 2026-08-18:** all three strategies run. The budget reaches the handle (`genai_handle.rs:859`, set from `agent_manager/models.rs`), `enforce_context_budget` is called per request (`:1100`), and `Summarize` makes a real LLM call through `summarize_via_backend` rather than leaving its placeholder (`:1106-1128`) |
| 2026-03-21 | Agent undo: git-based + message rollback | Most valuable undo is file changes. Git stash before tool execution, apply on undo. Non-git: file journal. UndoTree<T> already exists in crucible-core. /undo slash command matches Aider pattern |
| 2026-03-21 | Output validation: primarily Lua-facing | Interactive chat rarely needs structured output validation. Programmatic/Lua sessions (entity extraction, digest generation) need it most. Built-in validators (json, regex) + custom Lua validators. Validate→retry loop is the universal pattern across CrewAI, Agno, Semantic Kernel |
| 2026-06-28 | Second self-improvement avenue: reflection pass | Hermes Agent review showed knowledge insertion (write-notes-mid-turn) is reactive and misses learning the agent doesn't think to record. A forked background reviewer that *proposes* notes/skills after a finished session — never auto-merging, provenance-tagged so it can't touch human notes — is the complement. Deliberately avoids the `session-digest` failure mode (automatic LLM-judged merges → kiln pollution): propose, don't dispose |
| 2026-06-28 | Tool/skill access via progressive disclosure | Hermes Agent review: attaching every MCP/plugin tool schema every turn bloats context and degrades as servers proliferate. `discover_tools`/`get_tool_schema` already exist; add automatic budget-based deferral (search → describe → call bridge) with core tools never deferred. Same pattern unifies tools and skills (list → view → use) |
| 2026-06-28 | Dropped user-facing temperature / max_tokens knobs | The genai turn path never applied session `temperature`/`max_tokens` (advertised via `temperature_control`/`max_tokens_control` capability flags that had zero readers — dead code). Like Claude Code/Codex, Crucible doesn't expose these as interactive knobs: low temp is near-always right for tool-use, and a user `max_tokens` mostly just truncates output. Removed the dead capability flags and the interactive `:set temperature`/`:set max_tokens` (TUI) + `cru set` (CLI) surfaces. Programmatic config (agent cards, Lua, web API) retains the fields for the rare deterministic-extraction case. ~~**Confirmed 2026-07-30:** the retained programmatic surfaces are inert — `GenaiAgentHandle` has no temperature or max_tokens field, so the Lua binding, the RPC setters, the agent-card frontmatter and the web `PATCH` route all write a field nothing reads~~ **Annotation struck 2026-08-18:** both fields now exist on `GenaiAgentHandle` and both reach the request — `genai_handle.rs:396,398` declare them, `:881-885` apply them to `ChatOptions`. The decision itself stands: they remain programmatic-only, with no interactive `:set` |
| 2026-06-28 | Execution backends stay plugins, not core | Confirmed by Hermes Agent contrast: Hermes ships 6 hardcoded backends (local/Docker/SSH/Singularity/Modal/Daytona) in core. Crucible keeps the agent backend-agnostic and routes alternate execution through `pre_tool_call` hooks — the `oci` plugin is the reference. Docker/sandbox isolation is plugin territory; the daemon never grows a per-backend abstraction |
| 2026-08-11 | Delete the graph query pipeline (`storage/sqlite/query/`) | ~5,739 LOC implementing an IR, four syntax front-ends (cypher/PGQ/jaq/SQL-sugar) and a SQLite renderer, unreachable from any RPC method. Deleted not for want of callers — that argument was raised in July and rightly rejected — but because the renderer targets a schema that has never existed: it defaults to an `edges` table absent from the codebase, and `for_crucible_eav` joins on `entities.path`, a column `entities` does not have. Both committed golden SQL strings fail to prepare. Wiring it up means retargeting the renderer, regenerating all 17 snapshots, solving the `Scope` enforcement that the raw-SQL hatch is test-gated to avoid, and choosing among four syntaxes when the (since-deleted) design note concluded "skip DSL entirely" — the working part is the part thrown away. Reversible: the deletion SHA is recorded in the deletion commit |
| 2026-08-11 | Delete `SessionIndex`, accept slower session listing | 513 LOC of a JSONL-directory cache that production never constructs, so the `sessions` table is never created. Deleting it forfeits the designed fix for a regression the session-log read-path fix introduces: `session.list_persisted` and `session.reindex` parse every log in a loop, work they currently skip only because parsing fails. Accepted knowingly — the cost is latency, not correctness, and 513 LOC is recoverable from git with full context if it bites. Residual gap recorded on purpose: the slowdown is unmeasured, so a timing assertion is worth more than a rebuilt index. A future fix must *build* an invalidation story, the part `SessionIndex` never had |
| 2026-08-11 | Fix the Lua kiln graph functions; delete the abstraction behind them | `cru.kiln.outlinks()`, `backlinks()` and `neighbors()` return an empty table in production always — the plugin loader never binds them, and their only coverage asserts against a `MockGraphView` production never constructs. Chose to wire them over `NoteStore`'s existing `backlinks`/`inbound_links`/`graph_links` rather than withdraw the API: removing a documented surface to resolve a bug is the worse trade. The `GraphView`/`InMemoryGraph`/`SqliteGraphView`/`MockGraphView` axis (~1,000 LOC) is then deleted — the API survives, the abstraction does not |
| 2026-08-11 | `cru` stays one fat binary with multiple entry points | Considered rejection of a thin-client split, not a deferral. A single binary with several entry points is functionally equivalent to several binaries and cheaper in RAM and on disk than N binaries statically linking overlapping trees. `Server::bind_with_plugin_config` puts `cru daemon serve` in the CLI by construction, which made this a product question rather than a refactor. Consequence accepted: the build-time complaint that motivated the split now rests entirely on measurement, and if the daemon link rather than `fastembed`/`ort` dominates the release build, no lever remains. `fastembed` + `ort` are default-on and toggleable today, which is the cheaper thing to measure first |
| 2026-08-13 | Mobile gets a separate SHELL, not a responsive desktop layout | The desktop shell assumes a wide viewport: measured, at 780px the centre column collapses to 29px and the terminal renders one column. Rejected responsive-ifying it. Cheap because the seam already exists — `panel-registry` registers panels as bare components and `Pane` renders them through `<Dynamic>` with no pane or tab context, and only two files in the tree import `windowing/`. First pass: editor as the main area, file tree and session as edge drawers with tabs but no tab MOVEMENT (movement is where `windowing/`'s bulk lives), a kiln/project picker in the left drawer, no terminal, no vim mode |
| 2026-08-13 | Mobile lives on the SAME origin, manifest and service worker — no `/m`, no second bundle | Two PWAs on nested paths of one origin is what Chromium's own web-apps team calls "strongly not recommended": two manifests install as two apps, the outer captures the inner's links, and the inner's notifications are misattributed — none configurable away. `vite-plugin-pwa` cannot emit two scoped service workers, so a second shell would mean dropping `generateSW` and hand-writing the navigation route. Survey found 7 of 7 comparable self-hosted apps ship one web UI and zero ship `/m`; Discourse deleted its mobile template tree in 2025-26 citing maintainability, and Wikimedia retired m-dot while KEEPING its separate skin — which survived because it rides an extension point rather than forking the app. So: client-side branch at the root, one origin |
| 2026-08-13 | Mobile first pass is ONLINE ONLY; offline is separate product work | The editor earns its place as groundwork for offline capture, but offline reads and writes are deferred rather than bundled. Reads need `runtimeCaching`, which the service worker deliberately lacks — caching authenticated responses in a same-origin-writable store is the threat `pwa-scope.test.ts` exists to pin, so it needs an explicit answer on what may be cached and what happens on sign-out. Writes are a second writer against a daemon that owns writes, so they need an outbox, replay and a conflict answer; the failure mode is silent data loss, so it is sequenced last |
| 2026-08-13 | Deep links must use the hash, not a path | Forward-compatibility decided before anything ships, because published URLs are permanent. `navigateFallbackAllowlist: [/^\/$/]` serves the cached shell for `/` alone and the manifest `id` is pinned to `/`, so a path-based deep link (`/note?path=…`) would work online and fail offline — exactly when a home-screen shortcut matters — while widening the allowlist re-opens what `pwa-scope.test.ts` pins. `/#note=…` costs nothing today |
| 2026-08-13 | Pin the PWA manifest `id` explicitly | An absent `id` defaults to `start_url`, making `start_url` load-bearing forever: any later change — a mobile shell, a different landing route — turns every existing install into a SECOND app with its own icon, storage and notification identity, with no remote migration. The app is already installable, so this was one line now versus un-fixable later |
| 2026-08-19 | No session-resolution layer at the RPC routing step | The despaghettification plan's S3 said "forty handlers resolve a session; one place should". Measured against the tree, they do not: two places already resolve one (`SessionManager::get_session`, `AgentManager::get_session`), the ~40 handlers call through them, and most carry the id as an opaque key rather than wanting a `Session`. The blocker is not the resolution but the ANSWER — asked about a well-formed id belonging to nothing, the routed methods give **eight** different answers and **six of them succeed**: `session.cancel` reports `cancelled: false`, `session.cache_stats` a zero aggregate, `session.status` / `review.list_hunks` / `session.load_events` / `session.render_markdown` an empty collection, and `session.test_interaction` never reads the session at all. The eight lifecycle methods answer `Operation '{op}' not allowed in current state`, which never names the session. A resolver at the routing step that refuses an unknown session breaks six methods the web Inbox and the review panel poll; one that does not refuse leaves every handler its own second check. Serving all eight from one place means an eight-way per-method policy table — the match arm it was meant to delete, moved one file over. Pinned as a contract, not a to-do: `crates/crucible-daemon/src/rpc/missing_session_contract.rs` fails on any change to any of the eight |
| 2026-09-10 | `io.popen` and `os.execute` ship; `loadlib` and `os.exit` do not | The host held both back so that `cru.shell` would be the one gated door to a process. The door has no lock: `PluginShellPolicy::default()` blocks four command names with an empty allow-list, and `prepare_command` reads the command name and never the arguments, so `cru.shell.exec("sh", { "-c", … })` already runs anything — `runtime/plugins/oci` ships that call. A plugin is code the operator installed, and it gets the API the way an editor plugin gets the editor. `loadlib` loads native code no policy can read, and `os.exit` ends the daemon with every session in it. See `crucible-lua/src/luau_compat.rs` |
| 2026-09-01 | Reflection reads before it proposes; rejections are kept | The WikiSkill paper (arXiv 2608.27454) showed that two things make skill evolution work: a persistent record of the proposals a human rejected, and a maintainer that reads the knowledge base before it proposes. So `cru proposals reject` moves a file to `rejected/` instead of deleting it, the reviewer is told the recent rejected titles, and the reviewer searches and reads the kiln before it answers, and proposes an `update` of a note that already covers the idea rather than a duplicate. The same rules apply to the periodic consolidation pass. **No longer true 2026-09-14:** `cru proposals` and the staged file are retired; a pass writes its notes with `create_note`/`update_note` in its own session and the review ledger disposes of them. A reject reverts the note and the hunk leaves the composed diff, so no rejection history is kept and the reviewer is told none. The reviewer still searches and reads the kiln before it writes |
| 2026-09-12 | Settings on a phone drill in, one list at a time | A 216 px section list does not fit 412 px, and the strip of tabs that replaced it showed two labels of twelve. iOS, Android and Obsidian all drill. Depth is not capped: the daemon's config tree pushes a page per group. Each level takes a history entry, so the phone's back button walks them. | `MobileSettings`, `settings-nav.tsx`, Mobile Shell §10a |
| 2026-09-11 | Mobile vim mode is a separate setting, OFF by default — supersedes "no vim mode" (2026-08-13) | A phone has no `Escape` and no modifier row, so vim must not be the default. Removing it outright strands a user who pairs a keyboard with a tablet. One shared `editor.vimMode` cannot serve both shells, because a laptop window and a phone window can share one browser profile and `localStorage` holds one value; the compact shell reads `vimModeCompact`, and Settings shows both toggles, each labelled with its shell |
| 2026-09-11 | The mobile session drawer switches projects; offline keeps unsynced edits across a lapsed credential | The desktop's session rail is a recency Inbox over a project tree, and on a phone the tree is too long to scan, so the drawer's header chooses one project and lists its sessions; the Inbox stays cross-project because a session waiting on the user matters whatever is on screen. Offline: there is no sign-out, and none is needed — the browser holds a minted 30-day token in an HttpOnly cookie, never the key, and rotating the key already ends every session. A 401 during the drain keeps the outbox and asks for the key again; nothing wipes the mirror or the outbox on its own. Rotating the key stops sync but cannot erase a device's copy — what a lost phone should do is left open |
| 2026-09-11 | Mobile drawers: sessions and files are two tabs in the LEFT drawer; the right drawer holds Backlinks alone — supersedes the two-drawer split of 2026-08-13 | The two pickers are where a user GOES, and backlinks are the open note's CONTEXT; putting both pickers under one thumb means moving between a session and a note never crosses the screen. It also lands the picker where the 2026-08-13 row put it, "in the left drawer". Every other panel — Changes, Activity, Surfaces, Plugin Blocks, Search — opens from the overflow menu as a content tab, because a user visits them rather than keeping them beside a note. Whether a second pane earns the right drawer is left open; Crucible has no outline or tags panel to offer |
| 2026-09-11 | Notes autosave on desktop AND mobile; project files keep manual save | Manual save was the desktop default (`autosaveSeconds: 0`), and on a phone with no `Ctrl+S` it loses writing. A note now saves 2 s after its last edit on both shells, so one setting serves both and the phone needs no split key. Only a file inside a kiln autosaves: a save in a project can fire watchers and builds mid-edit. Every browser that ever saved a setting stored the old 0 explicitly, so settings gain a version and a one-time migration turns a stored 0 into 2; a user who wants it off turns it off again, and that is kept |
| 2026-09-11 | The desktop layout belongs to the desktop shell alone | The layout persists to the daemon (`POST /api/layout`), one per daemon, shared by every desktop. The compact shell never loads it, never saves it and has no concept of it — a phone that saved would overwrite every desktop's layout. The phone keeps its own tab stack in its own browser. Per-machine desktop layouts are a separate question, not decided here |
| 2026-09-11 | Offline caches a WHOLE kiln, the user chooses which, and nothing is ever wiped | A working set is a heuristic, and a user who wants a kiln on a plane wants the kiln, not the part a cache guessed at. So a kiln is kept offline or it is not: no cap, no eviction, no expiry, and it stays until the user turns it off. A settings group lists every kiln with a toggle and its size (the source of truth); the files drawer's root picker adds a long-press shortcut. Projects are not offered — they hold code the phone does not edit. On credentials: a lapsed or rotated key stops sync and touches nothing already stored, and the drain resumes when a new key reconnects. Remote revocation was never available — a web app cannot erase a cache on a device it cannot reach — so the cache is as safe as the device, as in every offline notes app. The hazard that IS real is an outbox replaying into the wrong daemon (a key names a daemon, not a person), so mirror and outbox bind to the daemon they came from — origin plus `config_root`, since no daemon id crosses the wire — and refuse to drain into another |
| 2026-09-11 | Attachments are a second, per-kiln choice: notes only, or everything | Notes are kilobytes and attachments are the whole budget, so a kiln's images cannot ride silently on "keep this kiln". Two modes beside the toggle: **notes only** (default; an attachment is fetched when first opened and then kept) and **everything** (notes and attachments at once), for the user who wants a kiln on a plane with its images present. Three constraints come from the bytes themselves: text is `GET /api/kiln/file`, which 415s on non-UTF-8 and points at `/api/file/raw`, so attachments are Blobs and not strings; `/api/file/raw` deliberately serves documents inert (`nosniff`, `Content-Disposition`, octet-stream, and a `sandbox` CSP for SVG) while a `blob:` URL carries none of that and inherits this origin, so a cached binary renders only through `<img>` and anything needing a document context re-fetches online; and attachments are read-only, so none of the write or conflict rules touch them |
| 2026-09-14 | A stale note write is MERGED, and a conflict is an entry the app lists — the conflict copy is retired | The copy lost no bytes, which was its whole defence, but nothing listed it: a user met a dated second note by accident, weeks later, or never, and two notes with one name are worse than one note with a question in it. Every write now carries the text it was made from beside its base hash, so the daemon can run a three-way line merge under a per-path lock: writers who touched different lines both land with no question asked, and only a line group both changed differently stops the write. That becomes a conflict in the outbox, holding the merged text and its regions, counted apart from the unsent edits because sending again can never settle it, and opened from the phone's badge, the More sheet or the Changes panel. No CRDT: the truth is markdown on disk that the agent, the TUI, the CLI and any other editor may rewrite, and a CRDT needs every writer to speak it |
| 2026-09-15 | The session rail's Inbox is the last five sessions, and the tree below draws only the rest; a project with no session takes no row | The Inbox rule was "not idle and touched in the last day", which made it a status filter: empty on a quiet morning, and it dropped the session the user was in a minute ago as soon as the agent went idle. An inbox answers "where was I", so recency alone decides and it stops at five. The tree no longer repeats an Inbox member — one session, one row — but keeps the member's project header, without a chevron when nothing is left under it, because New Session lives on that row. Detected projects with no session used to sit behind a counted "No sessions" fold; a directory the user never worked in is not a place on the rail yet, so it appears the moment a session starts in it. The phone's Sessions tab follows the same two rules |
| 2026-09-15 | The default prompt asks for a `[[wikilink]]` wherever a note is mentioned, replies included; the renderer links nothing else | The prompt asked for wikilinks "when you write to the kiln", so a model that listed a folder in a reply echoed bare filenames, and the transcript showed text where the reader expected links. The renderer must not guess: linking every filename means asking the kiln which words are a title on every render, and a wrong guess paints a pill over prose. The model writes the link; the renderer keeps rendering only what it wrote |
| 2026-09-15 | A session's project (workspace) is fixed at creation; the daemon refuses `session.set_workspace` for every session, and the composer's project chip is a static label | The workspace is the agent's filesystem containment boundary and the project the session is filed under. Moving it mid-session re-scoped every later tool call, re-homed the transcript's row in the rail, and could not be followed by an ACP agent, whose process runs in the directory it was spawned with. The daemon owns the rule (`AgentError::WorkspaceFixed`, matchable by clients); the RPC stays on the wire so an older client gets a refusal it can show. Kiln attach/detach is unchanged: a kiln is knowledge, not containment. The chip stays on the row because it says where the session acts |
| 2026-09-15 | A registered kiln root is never a project, and a `kiln_path`-only config names its kiln after the directory | A session created with a kiln as its workspace auto-registered the kiln in `projects.json`, so the session rail grew a project header named after the kiln. The project manager now asks the kiln registry at every registration and every read: refused at `register`, left out of `project.list` and `get`, and not dropped at load because the registry grows while the daemon runs. A kiln inside a repository still resolves to the repository, which is a project. Separately, `kiln_path` defaults to the working directory and its synthesized entry was named "default", so `cru --standalone web` run inside a kiln listed that kiln as "default"; the entry now takes the directory basename, and "default" survives only as the `default_kiln` pointer or as the name a user declares |
| 2026-09-15 | The web composers offer no agent card field | A card names a subagent, or an `@` callout inside a message. A field on the draft composer and on the phone's sheet made it read as a per-session choice beside model and kiln, which it is not. The daemon keeps `agent_card` on `session.create` for the CLI and for callers that mean it; the web draft never sends one |
| 2026-09-15 | Both web composers are one core: the capsule plus a data-built chip row under it; the prompt is a pill at one line; the mode control is a circle | The draft composer and the live session had drifted: the draft drew hand-placed chips ABOVE its field, the session drew a different set below. Now `ComposerCard` (textarea, mic, send — nothing else) and one `ChipRow` are the only composer, and each surface hands the row a `ComposerChip[]` list (key, axis label, value, what `''` means, options, how it renders); the draft lists kiln, project, workspace, runtime, agent and model, the session lists model, mode, project, kiln and status. An untouched axis reads as its resolved default marked `· default`, so a clean splash is a list of facts, not blanks. A chip is never inside the capsule. The prompt is a 9999px stadium while it holds one line and drops to the 18px card radius once the text needs a second line, because a tall stadium reads as a blob; the card states the count as `data-lines`. The mode control is a circle the height of the chips that wears the mode's icon; its list opens on hover, click and keyboard, with icons and descriptions for built-in modes and text for Lua-declared ones |
| 2026-09-15 | A session's own workspace folder is a file root, and the composer's target chips name the actual default | A session created with no project runs in `<session_scratch_dir>/<id>`, and the file tree's first listing of it came back "root is not a registered project" — true, and beside the point, since that folder is where the session's work goes. The daemon admits it wherever it admits a registered project (`fs.list_dir`, `fs.move`/`mkdir`/`trash`, `fs.write`, `search_grep`, the web file editor), matched by shape and by the session's record, so a stranger folder under the same base stays refused; the folder is still not a project. The chips read "Project default" when nothing was chosen, which named no answer; a provider now flags the row an untouched session gets (`default` on the runtime axis, `current` on the workspace axis) and the chip names it, because the provider owns that precedence and the browser must not re-derive it. The web unwraps a daemon refusal into its sentence and toasts it once per call, deduplicated, so a 422 is never the whole message |
| 2026-09-15 | The mocked browser tier is named `ui`; `live` is the only end-to-end tier, it runs ONLY the build this tree just produced, and it is hermetic | Twenty-eight specs called `e2e` mocked every API route with `page.route`, so each proved what a component does with an answer the spec itself wrote. Four defects on the session path shipped through a green run of them — a 422 on a session's own folder, a kiln the list offered and the attach refused, a stored session whose modes and models answered only after a history read, and the kiln switch — because a refusal the daemon issues is invisible to a fixture that answers 200. The tier keeps its value as component tests in a real browser and loses the name that overstated it. The live tier gains the opposite rule: it resolves the `cru` under this tree's target directory and serves this tree's `dist`, fails the run when either is missing or older than its sources, and never falls back to a `cru` on PATH, because a tier that silently tested an installed binary reported a pass for code it never ran. It is hermetic by construction — own HOME, XDG roots, `CRUCIBLE_HOME` and config dir, inherited `CRUCIBLE_*`, provider credentials and proxies dropped, a fake Ollama server as the only reachable model — and `lane-guard.live.spec.ts` asserts each of those from inside the run rather than trusting the setup that wrote them |
| 2026-09-15 | The composer's chip row folds; it never shrinks a chip, and a session's own folder is named, not spelled | A chip that shrinks loses its text, and the first casualty was the project chip of a session with no project: its workspace is `<session_scratch_dir>/<id>`, so the chip wore a 36-character session id, took the most width on the row, and told the reader nothing. It reads "Session folder" and keeps the path in its title. The row then answers the width question by COUNT rather than by size: each chip states a `priority` its surface owns, the row shows as many whole chips as it holds, and the rest fold into a `+N` button that lists them as full rows, each keeping its own picker. Truncation was the alternative and it is worse — an ellipsis in a model id or a branch name hides exactly the part that differs. Measuring this needed two rules the browser taught and no test had: a width is remembered per chip, because a folded chip is not in the document to re-measure, and the pass that draws every chip to measure it must read a microtask later, because Solid holds a signal written inside an effect until the update cycle ends |
| 2026-09-15 | A kiln name keeps its case and may hold a space, the registry is the only source of one, and no kiln is ever called "default" | Three faults, one cause: names had two sources and one charset nobody chose. `kiln.list` labelled an open-but-unregistered directory with the basename it WOULD have derived, and `session.connect_kiln` answered 422 `Unknown kiln "docs"` for that exact label — the picker offered what the daemon refused. Opening a directory now registers it (`KilnManager::open` → `KilnRegistry::register_discovered`, origin `discovered`, memory only, floor enforced), the listing reads the registry alone, and a row the floor refused says `registered: false` instead of wearing an invented name; one shared gate, `resolve_scope_kiln`, answers both the attach and the listing's own test. `KilnName` keeps the spelling its owner wrote and folds ASCII case for resolution, so `Crucible Help` renders as written and `crucible help` attaches it; the overlay and the state store fold too, or one name would arrive as two entries. The setup wizard named its kiln "default", which put a kiln called "default" in the first picker a new user ever opened; it now takes the directory basename, writes no entry at all for a path that names nothing, and the last-resort default is the bundled `crucible-docs` corpus — a real directory — rather than a pointer to nothing. The same rule decides what a starting daemon opens: the boot list read the manager (empty on a fresh process) plus the PROJECT registry, so a kiln root opened only because it was also a project, and when kiln roots stopped being projects nothing opened them at all — every kiln was closed after a restart, `kiln.list` reported none, and the kiln-addressed web routes 404'd against a kiln the user could see in their own config. Boot now asks `KilnRegistry::eager()`, which is what `lazy` has always meant and what the config reference already promised; the identity stays the registry's and the open state stays the manager's. The entry synthesized from `kiln_path` is lazy for the same reason it is not a declared kiln: that field defaults to whatever directory the client stood in when it spawned the daemon, so an eager synthesis had `cru web` open and index a source tree at boot. The daemon cannot tell a `kiln_path` the user wrote from the default — provenance is `#[serde(skip)]`, so the value arrives with the default already applied — and guessing is the inference the registry exists to refuse; a user who wants the eager rule declares the kiln under `[kilns]`, which the config reference already recommends. "Which directories are kilns" is the registry's question and the listing now answers it from there, marking each row `open` and leaving out a registration whose directory is gone; a closed row is not a dead one, because every storage handler already opens on first use |
| 2026-09-15 | Every transcript row ends in ONE action column, and a prompt is the width of its own text with the sent time inline on its last line | The actions used to hang under the turn on an absolute strip, so every row reserved a band of empty pixels for them (`pb-5`) plus a margin to clear it (`mb-6`), and a prompt reserved a different one (`mb-5`). The largest gap in the transcript was therefore empty on purpose, and the distance between two rows depended on which kind came first. The strip moves into a fixed column at the right of the row (`--cru-turn-gutter`), which every row draws — prompt, turn, and a system row that draws it empty to hold the reading edge — and which costs no vertical space at all; the assistant's elapsed time reads there too, left of the buttons, because it measures the turn rather than saying anything the prose says. The remaining space between rows is one token (`--cru-turn-gap`) that the list spends once. The column comes OUT of the chat measure, not in addition to it, so the reading text keeps the composer's edges; the cost is that a very narrow pane still pays the full column. On the prompt: a bubble the width of the pane with three words in it reads as dead space with a sentence in one corner, so `.user-quote` is `fit-content` under a clamp. Its time is hover-only, and it is an INLINE trailer on the last line rather than a caption row or an absolute label — inline is the only one of the three that both reflows with the text and leaves the box identical at rest and on hover, since only opacity changes. A caption row costs a line of height on every prompt; an absolute label needs reserved padding, which is the dead space the pass set out to remove |
| 2026-09-16 | A daemon that fails to start is almost never doing slow work; look for an abort first | `cru daemon restart` reported "failed to start within 5 seconds" the day registered kilns began opening at boot, and the obvious reading was that the boot now indexed the docs corpus. It did not. The socket binds 58 ms in, the kiln open is a spawned task behind it, and opening a kiln runs no pipeline at all — the index is derived data that stays in the kiln and is read back, so a warm `cru process` over 184 notes costs 0.02 s against 93 s cold. The daemon was aborting. Both sites are guarded — a Lua error is caught and logged, and `BasicMarkdownItExtension::parse` wraps the parser in `catch_unwind` — and neither guard can run, because the release profile sets `panic = "abort"`. The guards are inert in every shipped build, which is the decision this row exists to surface: a panic-guarded subsystem and `panic = "abort"` cannot both be right. Fixed here: the parser bug, and a check-then-act race that opened one kiln twice at boot (two SQLite pools, two pipelines, two watchers on one directory) |
| 2026-09-16 | The sessions rail and the files rail are fixed, and the rail's `…` is the layout control | A user could close the session list and the file tree, and a restore brought the emptied rail back empty, so the shell opened with no doorway and no control that could re-add one; the only repair was a settings page the user had to find while looking at the broken layout.
